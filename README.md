# AI Chief of Staff — Morning Brief

A Python script that runs daily (cron, 7 AM) to collect data from your calendar, Gmail, Notion inbox, and local project/task files, then emails a synthesized morning brief generated by Claude.

## What It Does

1. Fetches today's and tomorrow's Google Calendar events (via `gws` CLI)
2. Fetches Gmail threads needing attention — unread or starred (via `gws` CLI)
3. Loads active projects from `data/projects.md` and due recurring tasks from `data/recurring.json`
4. Optionally fetches Notion inbox items (via Notion API)
5. Diffs yesterday's state snapshot against today to detect auto-resolved open loops
6. Calls Claude (`claude-sonnet-4-6`) to synthesize a morning brief: executive summary, top 3 priorities, watch-outs, schedule notes
7. Sends the brief as an HTML email to `trent@teambuildr.com` via Gmail OAuth
8. Writes a local `output/dashboard.html` for in-browser review
9. Saves a JSON state snapshot for next-day loop resolution

## Setup

### 1. Install dependencies

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 2. Configure environment

Copy `.env.example` to `.env` and fill in:

```bash
ANTHROPIC_API_KEY=sk-ant-api03-...
NOTION_TOKEN=secret_...          # optional, only if Notion is enabled
```

### 3. Copy Google OAuth credentials

This project reuses credentials from `../daily-sales-brief/` or `../shared/`:

```bash
cp ../daily-sales-brief/credentials/client_secret.json credentials/
cp ../daily-sales-brief/credentials/token.json credentials/
```

The token needs `gmail.readonly` and `gmail.send` scopes. If the token was created without `gmail.send`, run `python main.py --dry-run` once to re-authenticate via browser.

### 4. Edit `data/projects.md`

Format each project as:

```markdown
## Project: CRM Automation
**Status:** In Progress
**Next:** Deploy to staging
**Notes:** Uses Google Sheets as backend
```

### 5. Edit `data/recurring.json`

```json
{
  "tasks": [
    { "name": "Review sales pipeline", "schedule": "weekly", "day": "Monday" },
    { "name": "Check trial expirations", "schedule": "daily" },
    { "name": "Monthly metrics review", "schedule": "monthly", "day": 1 }
  ]
}
```

### 6. Set up cron (7 AM weekdays)

```bash
crontab -e
```

Add:

```
0 7 * * 1-5 /Users/trentluecke/dev/Claude-Projects/chief-of-staff/run_brief.sh
```

## Running Manually

```bash
# Full run (fetches everything, sends email, saves state)
python main.py

# Skip email send
python main.py --no-email

# Dry run — no email, state snapshot still saved
python main.py --dry-run

# Shell wrapper (used by cron, writes to logs/)
./run_brief.sh --no-email
```

## Configuration (`config.json`)

| Key | Default | Description |
|-----|---------|-------------|
| `email` | `trent@teambuildr.com` | Recipient email address |
| `gmail_profile` | `work` | `gws` profile for Gmail/Calendar reads |
| `calendar_ids` | `["primary"]` | Calendar IDs to fetch |
| `unread_email_max` | `15` | Max email threads to surface |
| `ai_model` | `claude-sonnet-4-6` | Claude model for brief generation |
| `notion.enabled` | `false` | Toggle Notion inbox collection |
| `dashboard_path` | `output/dashboard.html` | Local dashboard output path |

## Architecture Notes

- **No persistent server** — pure cron job, stateless between runs except for daily JSON snapshots
- **`gws` CLI** for all Google reads (calendar + Gmail); OAuth only used for sending email
- **Open loop resolution** works by saving a snapshot of open thread/item IDs after each run, then diffing against the next day's data to detect what auto-resolved
- **Notion integration** is optional and disabled by default; enable via `config.json` and set `NOTION_TOKEN`
- **Shared auth** reused from `../shared/google_auth.py`
